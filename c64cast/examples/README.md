# Example configs

Each TOML in this directory is a runnable single-scene demo of one
scene type or overlay. Use them when you want to *see* a feature in
isolation, without comments and unrelated scenes obscuring it.

They ship **inside the package**, so every demo runs the same way from a
source checkout, a `pip install`, or a `uvx` one-liner — referenced by name
with the `example:` prefix instead of a path:

```bash
c64cast --list-examples                  # every demo + a one-line summary
c64cast --config example:hello           # run one
```

`--list-examples` is generated by reading these files, so it is the index
that cannot go stale; this page is the narrative.

For the full annotated reference covering every option, see
[`c64cast.example.toml`](c64cast.example.toml)
(`c64cast --config example:c64cast.example`).

## Start here: `hello.toml`

[`hello.toml`](hello.toml) is the simplest demo and the recommended
first run. It scrolls big text across a solid canvas and needs **nothing
but a reachable Ultimate 64** — no webcam, microphone, SID files, video
clips, or optional extras. Every other demo assumes some piece of
hardware or media; this one doesn't.

```bash
c64cast --config example:hello -u u64://YOUR-U64
```

Edit the `[ultimate64].url` at the top of the file (or pass `-u`) and you
should see scrolling text immediately.

## Running

```bash
c64cast --config example:overlay-clock
```

Any `-u/--url`, `-A`, or other CLI flag still overrides the config. An
`example:` config is read-only for practical purposes — it lives inside the
installed package — so to make one yours, copy it out first:

```bash
c64cast --print-example hello > c64cast.toml
```

## Single-scene mode

When a config defines exactly one scene, the Playlist enters
**single-scene mode** automatically:

- No interstitial appears between cycles.
- The scene loops forever — when `duration_s` expires (or
  `process_frame` returns False), the scene tears down and sets back
  up to run again.
- CTRL key skip events are ignored (there's nowhere to skip *to*).
- The C= (Commodore key) pause/resume still works.
- `[playlist] interleave_videos` is ignored (an inserted video would
  promote the playlist to multi-scene mode and defeat the demo).

Exit with `Ctrl+C`.

## Demos that need something extra

Most demos run against a bare U64 plus whatever is already on your
machine. Three groups need more, and each file's header comment says so:

- **An optional extra** — `video` (PyAV) for the video demos, `mic`
  (sounddevice) for the mic/spectrum ones, `midi` for the MIDI and ASID
  scenes, `vision` (MediaPipe) for the gesture demos. `c64cast --doctor
  --skip-probe` reports which are installed.
- **Your own media.** The demos that play a file point at `assets/` — a
  directory that ships empty (media there has unclear licensing or is
  personal). `--list-examples` tags each of these `[needs your own media]`;
  drop files into `assets/<kind>/`, or edit the scene's `file =` to point
  anywhere.
- **More than one C64** — the `ensemble/` demo (see below).

The waveform, MIDI, and ASID scenes drive the U64's SID chip directly and
ignore the `[audio]` section.

## Ensemble demo

`ensemble/` is a 3-system video wall with a cross-system `big_text`
scroll:

```bash
c64cast --config example:ensemble/master
```

See [`ensemble/README.md`](ensemble/README.md) for a walkthrough of the
cross-system orchestration model. Unlike the single-scene files, it needs
at least two reachable U64s on the LAN (or one real + a stub).

## Editing a demo for yourself

Copy one out with `--print-example NAME` (above) into your working
directory as `c64cast.toml`, then edit it. For combining overlays,
swapping display modes, and everything a single demo leaves out, the
kitchen-sink reference at [`c64cast.example.toml`](c64cast.example.toml)
covers every option.
