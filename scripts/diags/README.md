# scripts/diags — reusable diagnostic / investigation tools

Committed home for the throwaway-but-recurring tools used during feature work
and hardware debugging. Before this directory existed they were re-created each
session in `/tmp` (with the usual `/tmp` vs `/private/tmp` and project-home
papercuts) and each invocation needed a fresh permission approval. Committing
them gives stable paths, a single permission allowlist entry, and a place to
improve them over time.

These are **dev tools, not part of the shipped package** — they live under
`scripts/` alongside `bench.py` / `fake_u64.py`, are not imported by
`c64cast/`, and are excluded from the wheel and from `mypy --strict`.

## Conventions

- **Shared helper:** [`_diaglib.py`](_diaglib.py) solves path/import handling,
  hardware defaults, and the U64 REST shims once. Every tool does
  `import _diaglib as d` and runs from anywhere (it inserts the repo root onto
  `sys.path`, so `import c64cast` works regardless of cwd).
- **Run them** with the project interpreter so `import c64cast` resolves:
  `uv run scripts/diags/<tool>.py …`, or just `scripts/diags/<tool>.py …`
  when direnv has activated `.venv`.
- **Outputs** (captures, fixtures) land in `scripts/diags/out/`, which is
  git-ignored. Source tools are tracked; their artifacts are not.
- **Hardware defaults are env-overridable** because indices/IPs drift with
  hotplug + DHCP. The committed defaults are a working rig's values, not ground
  truth; set the vars for yours:
  | Var | Default | Meaning |
  |-----|---------|---------|
  | `C64_DIAG_URL` | `http://192.168.2.64` | U64 base URL |
  | `C64_DIAG_U2P_URL` | `http://192.168.2.65` | U2+ base URL |
  | `C64_DIAG_CAMERA` | unset | capture device: a cv2 index, a camera name substring, or a USB VID:PID. Unset, a tool opens the one connected camera that looks like an HDMI capture device (`c64cast.control.camera.looks_like_hdmi_capture`: a USB device whose name matches no webcam, phone or virtual-camera pattern); with none or several, it exits listing every camera rather than open one |
  | `C64_DIAG_CV2` | — | removed: a tool exits if it is set. Use `C64_DIAG_CAMERA` (index, name or VID:PID) instead |
  | `C64_DIAG_AVF_AUDIO` | unset | audio input for the ffmpeg/avfoundation tools: an index (`:N` or `N`) or a name substring. Unset, a tool records from the one audio input named like the capture camera (the tool's own `--device` where it has one, else `C64_DIAG_CAMERA`, else the auto-picked one); with none or several, it exits listing the inputs. The system default input is never used |
  | `C64_DIAG_SD_AUDIO` | unset | the same, for the sounddevice tools (`N` is a sounddevice index) |
  | `C64_DIAG_VERIFY_WIDTH` | `960` | longest-edge px for captures saved via `save_image` (downscale default) |
  | `C64_DIAG_LOCK_DIR` | `~/.cache/c64cast/locks` | where `hw_lock.py` keeps its per-device lock files |
- **One user of a rig at a time.** The DMA service takes a single connection
  and the capture device a single reader, so when more than one shell or agent
  can reach the rig, run every command that touches it under
  [`hw_lock.py`](hw_lock.py): `python3 scripts/diags/hw_lock.py <command…>`.
  It needs no project environment, so it wraps `uv run …` as readily as a tool.

## Tools

| Tool | What it does |
|------|--------------|
| [`hw_lock.py`](hw_lock.py) | Run a command under an exclusive per-user lock on one rig: waits (naming the holder on stderr), then execs the command, so its exit code and Ctrl-C are its own. `--device URL` keys the lock on the URL's host (`u64://H` and `http://H` share one); the default key suits a one-rig machine. Stdlib only, POSIX only. |
| [`u64_probe.py`](u64_probe.py) | REST reachability + DMA-service (port 64) check; `--reset` / `--reset-only`. |
| [`hdmi_capture.py`](hdmi_capture.py) | Grab still frame(s) from the Cam Link (VIC ground-truth) → `out/`. Downscales to `--width` (default 960px) so captures read back cheaply; `--full` keeps native 1080p for pixel-peeking. New capture tools should write via `_diaglib.save_image` for the same default, and read their kept frame through `_diaglib.read_frame`, which retries a no-frame read for `NO_FRAME_RETRY_S` (5 s) and then fails naming the likely causes. |
| [`audio_capture.py`](audio_capture.py) | Record Cam Link audio via ffmpeg/avfoundation + `volumedetect` level summary. |
| [`run_and_capture.py`](run_and_capture.py) | Launch c64cast with a config, capture A/V across the run, then stop + reset. |
| [`make_fixtures.py`](make_fixtures.py) | Generate synthetic tone/clip/test-pattern A/V fixtures for the video path. |
| [`video_render_probe.py`](video_render_probe.py) | Render a video through a display mode offline (no HW); reports per-frame bg0/$D021 flips, bitmap push churn, and **writes + modeled frame cost per region** (priced with the profile's measured link cost model) for flash/flicker and throughput diagnosis. Flags any region `write_region` split into more writes than pushing it whole would have cost. Also times **host CPU per frame** (decode / render) against that link cost and names which side, if either, binds the source frame rate — with `--threads 1` to compare machines by single-core speed, this is the candidate-board benchmark. |
| [`link_cost_model.py`](link_cost_model.py) | Measure what a write costs the **host link** in wall-clock time, as `max(floor, intercept + per_byte × B)`, and print what it implies for `write_region`'s chunking. Times bursts flush-to-flush and separates the fixed from the marginal cost with a two-stage fit. This is where `HardwareProfile.write_cost_*` comes from — re-run it per backend if firmware or transport changes. Resets on exit. |
| [`tr_spans_cost.py`](tr_spans_cost.py) | TeensyROM+ only: the host-side round trip of one WriteC64Mem against one WriteC64Spans at a grid of payloads, slice sizes and gaps, plus batched spans. The throughput side of the slicing trade; `halt_shape_probe.py` and `audio_fm_probe.py` (both take `--tr-slicing`) measure the NMI side. Resets on exit. |
| [`doublebuffer_tear_ab.py`](doublebuffer_tear_ab.py) | A/B single-buffer vs host-DMA double-buffer for scene-cut tearing on a bitmap + text-overlay scene. Builds an abrupt-cut test video, runs both paths on the U64, burst-grabs Cam Link frames, classifies top/bottom raster-split tears, and saves example frames. Resets on exit. |
| [`flicker_tear_ab.py`](flicker_tear_ab.py) | Measure how often, and *where*, the host-DMA `$DD00` bank swap lands inside the visible picture. Acceptance test for the `$D012` window gate in `modes_irq`'s two swap handlers: builds an 8-state test video whose period cannot alias with the 2-bank swap, runs flicker and plain hires, classifies each captured frame's rows against the known palette, and reports percent torn plus the seam position — the seam is the payload, since the halt hypothesis predicts where the swap lands, not merely that it is late. Read the phase logs' fps too: a fix that buys cleanliness with frame rate is not a fix. Resets on exit. |
| [`flicker_score_grid.py`](flicker_score_grid.py) | Score which blend pairs actually flicker, by eye, blind. This script IS `flicker.SCORED_FLICKER`, the table `[color].flicker_tolerance` cuts across — two fitted rules (a ΔY threshold, then a red-orange warmth axis) were each refuted by the first run they had not been fitted to, so the eligible set is a recording rather than a metric. Run it to re-score the table, to settle a pair whose tier is in doubt, or to score pairs another `host_palette` brings into range that nobody has judged. Nothing it shows is filtered by the table it feeds: each page's config sets `[color].flicker_score_pairs` to exactly that page's pairs, which replaces the blend set outright — no tier filter, no luma cap — because being bounded by the tiers would make a wrong one permanent (a pair scored `intense` is in no blend table, so it could never be rendered to be re-judged) and would leave an unscored palette unscorable. Positions are shuffled within a page and pages among themselves (seed printed, `--seed` replays it), pairs already scored loud never share a page with pairs scored quiet — a loud patch makes its neighbors unjudgeable, and anything unscored is dealt with the loud pool since an unknown among the quiet patches is what would spoil the readings that matter — and every page hides one solid patch as a negative control, since a solid cannot flicker and calling one unsteady means the reading is picking up something else. Must be watched on the C64's own display, never a capture preview — a capture beats against the field-rate alternation and shows the picture slowly flipping between two versions of itself, which is completely convincing on a still page and makes scoring meaningless; the calibration page runs a capture-based check that the source really is alternating, so a slow flip after it passes is known to be downstream. A calibration page comes first with its three patches named — the loudest pair the clamp allows, a solid that cannot flicker, and the one pair scored `none` — because otherwise the first scored page is judged against nothing and an all-quiet page is indistinguishable from not knowing what to look for. Pools are dealt alternately so a run of loud pages cannot walk the scale. Which pair sat in which slot, and what it scored last time, is revealed only after the last page. Self-paced: it waits on Enter, so **run it yourself**, not through an agent. Resets on exit. |
| [`dsp_ab.py`](dsp_ab.py) | Offline A/B of the host audio DSP chain on the 4-bit DAC stream (no HW): legacy vs `[dsp]` encode, objective metrics (RMS/crest/codes/loud-body DR/silence%) + reconstructed wavs to `out/`. Tune DSP params before spending a hardware capture. |
| [`dsp_noise.py`](dsp_noise.py) | Noise-stage A/B (no HW): legacy mic hard gate vs the DSP expander on the Kaggle speech-noise-dataset's matched clean↔noisy pairs. Reports gap residual, gate chatter (events/s), and speech retention; writes both reconstructed wavs to `out/`. |
| [`tr_dma_integrity.py`](tr_dma_integrity.py) | Soak the TR+ DMA path against RAM and attribute the failures: write leg vs read leg, per data line, mapped to expansion-port pins (D7 = pin 14 … D0 = pin 21). Stage 4 separates an address line from a data line. Nothing downstream of the expansion port is in the path, so a result here cannot be blamed on the VDC. Soak `$00,$FF` together: the failing condition is the full-bus low-to-high swing, so one payload on its own can read clean on a faulty link. Quiesces onto the VDC cartridge first so nothing else touches RAM during the soak; blanks the VDC + resets on exit. |
| [`tr_read_probe.py`](tr_read_probe.py) | TeensyROM+ ReadC64Mem (0x64FD) round-trip over `--tcp`/`--serial`: ROM read, RAM write/read compare, live `$028D` watch. No Cam Link needed. |
| [`tr_dma_cycleclean.py`](tr_dma_cycleclean.py) | Confirm the TR+ WriteC64Mem DMA is cycle-clean: hammer `$4000` while a fragile IRQ-driven BASIC border-cycler runs; the border keeps sweeping (alive) iff the running program survived. |
| [`vdc_probe.py`](vdc_probe.py) | Probe a **C128's VDC** (8563/8568) through a TR+ in the C128's C64 mode: presence / chip version / 16-vs-64 KiB VRAM (all non-destructive), then the host→VRAM poke rate and the VDC hardware block-fill/copy rates that decide whether a VDC display target is viable. Self-verifies every stage by reading VDC RAM back through the `$D600`/`$D601` porthole — **no capture card**. Optional `--pattern bars`/`bitmap` puts something on the RGBI monitor to eyeball. Blanks the VDC + resets on exit. |
| [`vdc_c128.py`](vdc_c128.py) | Launch the **C128-mode VDC cartridge** (`c64cast.hw.vdc_rom`) on a C128 through a TR+ and measure the resident-8502 blit path: the machine boots into native 128 mode, a resident loop takes over, and the host does a bulk DMA into C128 RAM plus a one-byte command instead of a porthole round trip per byte. Reports the host→RAM DMA rate, the RAM→VRAM blit rate, and the end-to-end frame time. **No capture card** for the pass/fail stages — the ROM's mailbox heartbeat proves it booted and is running. Optional `--pattern image`/`animate` for the RGBI monitor. Blanks the VDC + resets the C128 on exit (a plain reset alone leaves the RGBI output showing whatever this run left in VDC RAM — the VDC is a separate chip the C64/128 reset does not touch). |
| [`vdc_bit_soak.py`](vdc_bit_soak.py) | Soak the VDC cartridge's RAM→VRAM blit and attribute each lost bit to a VRAM data line (D0–D7) and to what the bit held before. A fault in one VRAM chip, its socket, or the VDC's data bus shows up on a single line. Swapping the two VRAM chips moves a chip fault by four lines; a fault that stays put is the socket, a trace, or the VDC, and swapping the VDC tells those apart. Default is 16 full 24,000 B frames of `$FF` over `$FF`, capped at 16,384 B on a stock 16 KB VDC (probed at startup); `--mixed` runs five before/after cases over the top half of the screen. Staging is verified before each case and re-checked after it, so a TR+ write fault into staging is flagged rather than scored as VRAM loss; the readback only cross-checks itself, so clear the link with `tr_dma_integrity.py` first. Blanks the VDC + resets on exit. |
| [`vdc_second_machine.py`](vdc_second_machine.py) | Re-run the VDC porthole findings on a **second C128** and print a transcript to paste back. Three results so far come from a single 8563 R8/R9 and cannot be separated from a fault in that one unit: single-bit VRAM errors after a polled blit that are *always* `XOR $40` (bit 6, always 1→0 — what one bad data line looks like); a `$D600` bit-5 blanking window that turns out to be a quarter of the frame but still cannot have the ready poll dropped inside it; and the fact that a discarded porthole write *shifts* the stream rather than corrupting a byte, because the update address does not auto-increment on a write the VDC threw away. Carries its own frozen probe cartridge rather than `hw/vdc_rom.py`'s, so numbers stay comparable across machines as the shipped ROM changes. Sweeps stream length against per-byte spacing (17 / 24 / 29 / 34 cycles) and reports the window in bytes *and* in milliseconds of blanking, so the number cross-checks the duty cycle independently. Reads VRAM until two passes agree — a lone readback corrupts a byte about one pass in twenty, which is the same size as the effect being hunted. Bounces a pattern off R18/R19 first and skips stages 4 and 5 if it does not come back: selecting a register means writing $D600, so on a link where that write is lost every readback describes some fixed byte pattern instead of the blit, and the numbers look like measurements. Tallies the intermittent hang and relaunches through it. **No capture card**, nothing judged by eye. Blanks the VDC + resets on exit. |
| [`vdc_preview.py`](vdc_preview.py) | **No hardware.** Show what an image becomes on the VDC in 640×200 8×2-color bitmap mode — runs the real `c64cast.hw.vdc` packer + simulator, reports the color-clash count (blocks with >2 colors), and can `--dump` the raw 24000-byte frame. Iterate on conversion quality offline. |
| [`tr_audio_sid_probe.py`](tr_audio_sid_probe.py) | Drive the TR backend's audio paths on HW + capture Cam Link audio (`volumedetect`): `--mode tone` (host-DMA NMI DAC) or `--mode sid` (run_sid_player). `--flash` adds a 1 Hz `$D020` A/V sync marker. Silences + resets on exit. |
| [`midi_drive.py`](midi_drive.py) | Drive c64cast's `[midi_control]` surface from a **virtual MIDI port** (no physical controller): sends notes/CCs/PC/MMC-sysex from a script (`--script`), one-shot (`--send`), or interactively (`-i`). Open the port before booting c64cast (point its `[midi_control].port` at it). |
| [`mahoney_slot_ring_probe.py`](mahoney_slot_ring_probe.py) | Drive the `--calibrate-dac` slot-ring primitive against one isolated SID source (`--source socket1\|socket2\|ultisid1\|ultisid2`) and **save the raw captures to `.npy`**, so the alignment/extraction can be re-run offline with `--replay` and no hardware. Prints per-ring diagnostics, the merged 256-code ladder, and the volume-0 self-test. `--rounds N` sweeps how many slot-order rotations get averaged. `--source ultisid1` is the only way to measure an emulated core alone at `$D400` — `--calibrate-dac` measures physical sockets only — and is how the shipped `MAHONEY_ULTISID` table is re-derived. Restores the SID config and resets on exit. |
| [`dac_curve_playback_ab.py`](dac_curve_playback_ab.py) | Objective A/B of the `$D418` DAC curves: plays one test tone through the real encoder per curve (`linear` / `mahoney_ultisid` / the applicable calibrated table), captures it, and reports SNDR + THD at full scale and −30 dBFS. Use this rather than listening — the curves differ by several dB in loudness, which a level-mismatched ear reads as "better". |
| [`two_sid_dac_probe.py`](two_sid_dac_probe.py) | The two-SID `$D418` DAC's feasibility probe (#590): each chip's slot-ring ladder, the second chip's gain ratio and additivity at each mixer level, SNDR of a tone through the one-chip and pair tables, and the coarse ladder again at the end for stability. `--rate-sweep` instead times the one-ring, two-ring and pair NMI handlers against the sample rate (`--dma-load` adds render-path DMA). `--pair arm2sid\|ultisid` picks the two chips; `--replay DIR` recomputes each candidate table's dense bits from a saved run offline. Restores the SID config and mixer, silences and resets on exit. |
| [`midi_monitor.py`](midi_monitor.py) | The read counterpart to `midi_drive.py`: **print what a physical controller sends** and the exact value to paste into a config (`pad = N`, `type = "cc", number = N`). Lists/selects the input port (substring `--port`, or a numbered prompt), streams each note/CC/PC/pitchbend, and on Ctrl+C prints a summary table that separates a fixed-note pad from a full-sweep knob/fader. Hides MIDI clock unless `--clock`. Reuses `classify_message`, so it reads a controller identically to the live listener. Needs the `midi` extra. |

## End-of-session rule

Anything that drives the machine should leave it clean: `run_and_capture.py`
resets on exit by default (`--no-reset` to keep state), and
`u64_probe.py --reset-only` is the manual hook. Silence the SID (`$D418` = 0)
and disable CIA #2 NMIs before you reset, or the next run inherits a screaming
chip and a live NMI source. The VDC tools follow the same rule for the RGBI
output, which a plain C64/128 reset does not touch: `vdc_probe.py`,
`vdc_c128.py`, `vdc_second_machine.py`, and `tr_dma_integrity.py` all blank
the VDC and reset on exit (`--keep` / `--no-reset-exit`, tool-dependent, to
override).
